# ADR 0002: 図にすべきかの判定に Jev を使い、Jev を必須にする

## ステータス

採用 — 2026-10-16（判定に Jev を使うことは 2026-10-04 に決定）

## コンテキスト

参考にした qa-guide は、質問のたびに AI 解説を作る。毎回の呼び出しは費用がかかり、表示もうるさい。図が要るときだけ動く仕組みにしたい。

「図にすべきか」を毎回 Claude に判定させると、判定のたびに Claude の使用量を消費する。TypeSafe の Jev は、文章を生成せず、型の決まった判断と確率を返すモデルで、入力 100 万トークンあたり $0.042（出力無料）。手元の試験では、1 回の判定が入力 304 トークン（約 0.002 円）だった。

Jev は無料ではなく、API キーが要る。キーを持たない利用者をどう扱うかを決める必要があった。

## 検討した案

| 案 | キーがない利用者 |
|---|---|
| A | Jev なしでも動く。自動では図を出さず、コマンドで呼んだときだけ描く |
| B | Jev の代わりに Claude が毎回判定する |
| C | Jev を必須にする |

## 決定

C を採る。Jev による安い判定がこの MOD の強みで、Jev なしで動かすと汎用の図解ツールになり、作る意味が薄れる。B は、避けたかった「毎回呼ぶ」に戻る。

## 結果

- キーがない利用者には、ペインで導入手順を案内する（R9）
- README に Jev が必須であることと、Jev の導入手順を書く（R10）
- キーはプラグインの設定項目（`sensitive: true`）で受け取る。デスクトップアプリの MOD からは zsh の環境変数が見えないため（2026-10-16 の試験で確認）
- 外部サービスが 1 つ増える。Jev が止まっても、提案が出なくなるだけで、Claude の作業は止めない
